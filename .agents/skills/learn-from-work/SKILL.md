# Learn From Work

把 AI 已完成的工作轉成使用者能理解、解釋、驗證及遷移運用的知識。
完整度來自教材與練習的涵蓋，不是一次輸出所有內容，也不是把每次開發變成考試。

## 啟用與結束

- 只在使用者明確呼叫 `/skill:learn-from-work` 時啟用；後面的自然語言是本次學習要求。
- 不因一般開發、排錯、review、完成任務或提到「學習」而自行載入。
- 預設學習「目前對話中，最近一個可辨識的 AI 工作單元」，不是整個 repository。
- 使用者可指定某次修改、檔案、概念、測驗、練習或複習卡，不需要遵守參數格式。
- 學習可以跨多輪。使用者要求停止、結束或返回開發時，本次教學結束；不要在之後的一般任務自動延續。
- 完成後不自動寫入 profile、進度、wiki、記憶或其他檔案，也不安裝 hook、extension 或排程。

## 安全與權限

此 Skill 是教學指引，不是 sandbox、runtime gate 或額外授權。

- 預設唯讀：可以讀取範圍內、非機密的教材與必要的本機 repository evidence；不改程式、不修錯、不執行專案程式、測試、建置、安裝或部署。
- 不因「練習」而執行 shell、repository scripts、陌生程式碼或有副作用的工具。
- 可在聊天中提供非執行的程式片段、偽碼、diff 草稿或測試案例構想，明確標示它們尚未套用或驗證。
- 只有使用者明確要求才提供可執行命令；仍須遵守上層的 secret、Git、遠端及基礎設施限制。
- 使用者要求修改或執行時，先離開純複習範圍，依上層授權與相應領域流程處理。不把 Skill 呼叫視為修改 target repository 的授權。
- 不讀取 secrets、credentials、private keys、`.env`、raw kubeconfig 或 generated credential files；不要請使用者貼出它們。
- 不為補足教材自行查詢 live Kubernetes、Argo CD、GCP、CI 或 remotes。需要新的調查時，說明缺口並確認範圍。
- 本公開 skills repository 不保存私人專案教材或學習紀錄。引用當次工作只留在對話中；可重用範例採 placeholders 與保留的 example domains。

## 教材與模式

開始前完整讀取 [證據與教材規則](references/evidence.md) 及 [教學方法](references/teaching-method.md)。
需要設計題目、測驗、練習或延後複習時，再讀取 [練習與評量](references/practice.md)。
輸出結業或暫停摘要前讀取 [複習卡模板](assets/review-card.md)。不要一次載入所有專案來源。

| 使用者意圖 | 本次安排 |
| --- | --- |
| 沒有指定；完整學習 | 預設完整回顧：問題 → 改動 → 機制 → 取捨 → 驗證 → 練習 → 複習卡，分輪進行。 |
| 快速回顧 | 一張工作地圖、關鍵機制、主要風險、一次理解檢查與簡短複習卡。不是省略證據邊界。 |
| 深入某個概念或檔案 | 保留與整體工作的連結，聚焦指定主題；必要時逐段解說，不機械地逐行唸碼。 |
| 考我、只做測驗 | 先給無答案題目；依回答回饋，缺口才補課。允許直接索取答案。 |
| 讓我自己做 | 設計聊天內的小型仿作或除錯題；先不給答案，不自動修改來源。 |
| 隔日複習、重新複習 | 優先使用使用者提供的複習卡或可見的前次摘要；先回憶與遷移，再補讀教材。 |

不要在使用者已選好時再問模式。未提供程度或時間時，從少量前置概念開始，依回答調整；
使用者說時間有限時縮小課程，不宣稱能在固定分鐘內學會。

## 完整學習流程

### 1. 鎖定工作與教材

1. 從本次請求、可見對話、剛才的完成摘要與驗證結果，辨識單一工作單元。
2. 說明範圍，例如「這次複習輸入驗證的修改，不涵蓋整個後端」。
3. 對必要的具名檔案、diff、最近的 caller/default/test 做 bounded 唯讀檢查。
   先辨識 Git owner、branch 與 working tree；不是 repository 的文件也可作教材，不能假造 Git evidence。
4. 若有多個合理目標，或 compact/新 session 讓原始工作不可見，只問一個定位問題。
   不得聲稱記得不可見的工作，或把所有 dirty changes 都當成 AI 的成果。
5. 明確區分已知事實、尚未驗證的推論、教學用假設與缺少的資料。缺少完整 diff 時可教概念，但不能捏造 before/after。

### 2. 建立工作地圖

用簡短但具體的地圖回答：

- **原始問題：** 使用者想達到什麼？原本哪個行為或限制需要處理？
- **完成內容：** 哪幾個改動各自負責什麼？哪些範圍沒有改？
- **作用機制：** 輸入或事件 → 主要步驟 → 輸出或效果；設定、文件、診斷也用相應因果鏈。
- **驗證現況：** 有什麼證據支持，什麼尚未證實？
- **學習目標：** 完成後使用者能獨立解釋或完成什麼？用可觀察行為，不用「熟悉某技術」。

選出本次關鍵概念與先備知識，通常先排三到五個；依工作複雜度增減。
完整課程可涵蓋更多概念，但必須分段，不能無限制延伸。

### 3. 校準理解，不先考倒使用者

第一輪給工作地圖、教第一個關鍵概念，再提出一個能校準理解的小問題，然後等待。
若使用者已有明確程度，直接配合；不要先要求填寫個人 profile。
「不知道」是需要示範的訊號，不是失敗。允許跳過提問、直接聽講或隨時要求答案。

### 4. 逐概念教學

每個概念使用以下循環，具體方式見教學方法 reference：

1. **定位：** 對應本次哪個檔案、片段、決策或檢查。
2. **機制：** 說清楚輸入、狀態、控制/資料流、限制與結果，必要時使用小圖或具體案例。
3. **意義：** 為什麼這裡需要它？不用它或改成另一種做法會怎樣？
4. **取捨：** 解釋與此次需求相關的替代方案及代價；不替 AI 捏造當時的內心推理。
5. **理解檢查：** 一次問一題回述、預測或選擇理由題，等待使用者回答。
6. **回饋：** 點出正確部分及具體缺口，提供適量提示或示範，再決定補課或前進。

不要每個概念都硬套所有題型。不要將「點頭」當成理解，或用術語數量當成程度。

### 5. 教會驗證與除錯

- 解釋已用過的驗證如何對應需求、覆蓋了哪些行為、漏掉哪些情境。
- 區分「有測試檔」「執行過」「這次通過」「能證明需求」，四者不是同一件事。
- 示範如何從症狀 → 可區分的假設 → 最小檢查 → 結果解讀；不要把猜測說成根因。
- 至少涵蓋一個與本次工作相關的邊界或失敗案例。
- 不自動重跑先前測試，不以 source、render 或 CI 結果冒充 deployed/runtime truth。
- 教學中發現疑似問題時標示證據與不確定性；不偷偷修正，也不為了維持課程敘事隱瞞。

### 6. 從看懂到自己做

讀取練習 reference，依程度安排以下階梯中的適當步驟：

- **回述：** 不看原文，用自己的話說清楚機制。
- **預測：** 改變一個輸入或條件，預測結果並說理由。
- **仿作：** 以新的合成例子完成相似的小片段、設定草稿或檢查設計。
- **遷移：** 換一個條件，決定原方法是否仍適用，並提出調整。

完整模式預設包含至少一次理解檢查及一次仿作/遷移邀請；不是強迫完成。
一次只出一個任務，明確說明目標、限制、提交形式與判定標準，再等待。
不要同一輪把答案放在題目下面。使用者求解或卡住時按提示階梯協助。
聊天中的正確草稿不代表已通過真實編譯、測試或部署。

### 7. 總結、能力狀態與複習

使用複習卡模板在聊天中整理：工作地圖、核心概念、設計取捨、驗證邊界、
目前可獨立完成的部分、需提示的部分、尚未評量的部分、無答案回憶題與下一個練習。

- 只依可見回答描述能力，不打出假精準分數或保證已學會。
- 使用者只聽講或跳題時，標示「尚未評量」，不要當作答錯。
- 使用者可自行在下一次、隔日或較久之後回到複習卡；本 Skill 不會自動提醒。
- 複習卡不自動持久化。想保存時，先確認目的地與公開/私人內容邊界，依上層規則處理。
- 提供一個明確的下一步；若使用者要停止，允許用部分完成的卡結束。

## 回覆原則

- 預設使用台灣繁體中文；程式碼、API、路徑、設定鍵與錯誤訊息保持原文。
- 教學可以深入，但每輪先給當下需要的內容；不要把整份 Skill 印成教材。
- 提問後等待回答，不自己替使用者回答再宣布理解檢查通過。
- 用「在目前可見的片段中」「這是教學用假設」「結果未執行」標示證據邊界。
- 不要求每一步重新批准教學；只有目標不明、權限/範圍改變或保存內容時才確認必要事項。
- 不改常態開發流程，不新增自動觸發，也不為了追蹤學習建立額外 runtime。
