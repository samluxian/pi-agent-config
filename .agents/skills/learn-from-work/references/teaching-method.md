# 教學方法

## 目標：從接受產物到能獨立判斷

教學不是重播 AI 做過的每個動作，而是協助使用者建立四種能力：

1. 解釋需求、改動與機制的因果關係。
2. 在不同輸入或限制下預測結果。
3. 評估方案、風險及驗證的證據邊界。
4. 不照抄原文，也能完成相似的小工作或提出有效的除錯方法。

這些是學習目標，不是保證達成的成效。觀察回答與練習表現，不能由課程完成率推論能力。

## 第一輪怎麼開始

不要輸出完整長篇課程，也不要一開始就列一串問題。建議順序：

1. 說明這次複習的工作與可見 evidence。
2. 給一張簡短地圖：問題、改動、效果、驗證缺口。
3. 列出學習目標和接下來的概念順序。
4. 解釋第一個概念，以本次工作中的具體片段作錨點。
5. 問一個易於回答、能看出理解程度的問題，等待使用者。

使用者說「只考我」時，不先洩漏題目所測的答案；只交代範圍與作答方式。
使用者說「直接講、不用問」時，省略互動評量，最後標記能力尚未評量。

## 概念解說的固定骨架

每次選一個對本次工作有實質影響的概念：

- **位置：** 它在哪個檔案、段落、條件或檢查中？
- **白話：** 用一句話說它負責什麼。
- **具體追蹤：** 選一個非機密輸入，追蹤每一步及最後結果。
- **必要性：** 如果拿掉、換順序或改條件，會發生什麼？
- **取捨：** 與一個真實相關的替代方案比較。
- **限制：** 它不能解決哪些問題，證據目前到哪裡？
- **回憶或預測題：** 讓使用者用自己的話說明，再等待。

例如教材是一個「輸入 → 驗證 → 正規化 → 儲存」流程，就追蹤有效與無效輸入如何走，
而不是僅逐行介紹語法。若缺少必要的 caller，只說明可見函式內的行為。

## 深度調整

| 觀察 | 調整 |
| --- | --- |
| 不熟悉名詞或語法 | 補一個必要的先備概念，再回到實際片段。 |
| 能描述結果但說不出原因 | 用具體輸入逐步追蹤，問哪個條件造成分歧。 |
| 理解正常情況 | 加入空值、錯誤、優先序或其他相關邊界。 |
| 能解釋機制與邊界 | 加入替代方案、取捨與需求改變的遷移題。 |
| 回答跳躍或不完整 | 先釐清一個具體步驟，不一次補課全部概念。 |
| 使用者累了或時間不足 | 縮小到最重要的概念，產出部分完成的複習卡。 |

不要給使用者貼「初學者/高手」固定標籤。程度依概念而異，可能會程式語法但不熟部署。

## 有用的提問

優先使用需要理解機制的題型，不只考術語：

- **回述：**「這個改動是在解決哪個問題？用你自己的話說。」
- **預測：**「如果輸入缺少這個欄位，下一步會走到哪裡？」
- **反事實：**「如果拿掉這個檢查，哪種情況會出問題？」
- **辨識邊界：**「這個測試成功後，還有哪件事不能確定？」
- **取捨：**「在新限制下，你會保留原方案嗎？理由是什麼？」
- **定位：**「若出現這個症狀，你會先看哪個步驟？」

題目中的條件必須足夠。答案不能依賴教材未提供的外部狀態或冷僻知識。
避免誘導題，例如「這裡是不是為了更安全？」；避免只問「懂了嗎？」。

## 回饋與提示階梯

每次回答後：

1. 指出哪部分正確，引用使用者的具體推理。
2. 若有缺口，指出缺的是條件、流程、證據或取捨中的哪一項。
3. 只修正本次關鍵誤解；與題目無關的小問題可留到之後。
4. 根據需要採用下列最小足夠提示。

| 提示級別 | 做法 |
| --- | --- |
| 方向提示 | 提醒先看哪個條件或概念，不說出答案。 |
| 定位提示 | 指向相關片段，請其追蹤一步。 |
| 結構提示 | 給推理骨架、部分偽碼或完成一半的表格。 |
| 示範 | 展示解法和理由，再用另一個小例子檢查遷移。 |

使用者說「不知道」時先示範必要概念，不要求反覆猜；明確要答案時直接提供。
不要機械地走完四級。不能用讚美取代回饋，也不以錯誤羞辱使用者。

## 設計取捨怎麼解釋

對本次真的存在的決策，比較：

- 要滿足的需求與不可違反的契約。
- 採用方案的優點與成本。
- 一個合理替代方案，以及不選它的條件性理由。
- 哪個需求改變後應重新評估。

沒有 evidence 的性能或安全收益用假設表達，不宣稱「更快」「更安全」已測得。
避免製造本次不存在的架構需求。對簡單工作，說明局部決策即可。

## 驗證與除錯教學

### 驗證

把每個已有 check 對應到行為：

```text
需求 → 要觀察的行為 → 測試/檢查 → 可見結果 → 尚未覆蓋的風險
```

不要只解釋命令名稱。讓使用者知道「為什麼要看這個訊號」和「什麼結果會推翻假設」。
預期結果與實際看見的結果分開。測試沒有執行時只描述預期，不能用完成時態。

### 除錯

用以下框架回顧已做過的診斷，或設計聊天內的合成案例：

1. 先描述症狀，不先宣布根因。
2. 列出少量能被證據區分的假設。
3. 找到最小、允許且有判別力的檢查。
4. 解釋每種可能結果會讓哪些假設較合理。
5. 有資料才收斂；缺證據就標示尚未證實。

若原工作是未解決的調查，教會調查思路與缺口，不把它包裝成成功修復。

## 防止依賴與過度教學

- 先做一個示範，再把相似的小片段交給使用者，不全程代做。
- 提供關鍵資訊但不立即洩漏解答；也不為了「自主學習」隱藏必要前提。
- 教能遷移的機制，不要求背路徑、命令拼字或私人 identifiers。
- 一次只教當前工作所需的概念，對旁支可標記為之後的選題。
- 完整課程可以分很多輪，但使用者決定節奏，沒有必須通過的關卡。
- 不把所有討論都變成授權確認；讀教材與正常教學不需每輪批准。

## 暫停、跳過與返回開發

使用者可隨時要求更簡單、更深入、直接給答案、略過、只看摘要或結束。
中途暫停時產出簡短複習卡，標記已完成與尚未評量的部分；不指責進度不足。
若轉回開發，結束教學模式，遵循一般 repository 工作流程；不得把此 Skill 的
唯讀預設或教學問答套到所有後續任務，也不得繼續收集學習資料。
