# 練習、評量與延後複習

## 設計原則

每個題目都應對應本次一個學習目標，且在提供的資訊與安全邊界內能作答。
使用不同的合成例子測試遷移，不把私人資料搬進題目，也不以冷僻 trivia 增加難度。

預設作答在聊天中：文字說明、偽碼、程式片段、設定草稿、測試構想或因果圖。
這些都是未套用、未執行的草稿。不要把練習轉成 repository mutation 或 live 操作。
可執行命令只在使用者明確要求且上層規則允許時提供；命令的教學意圖不降低風險。

## 一個任務的格式

出題時包含：

- **練習目標：** 要測哪個能力。
- **已知條件：** 必要的輸入、假設與目前行為。
- **任務：** 一個可以獨立完成的小工作。
- **限制：** 不修改專案、不需查詢外部環境等。
- **提交形式：** 例如一句解釋加一段偽碼。
- **成功標準：** 可觀察且與題目直接相關的要求。

一次只出一題，等待回答。不在同一輪列出答案、解答連結或會揭露答案的詳細提示。
可以在內部準備評分準則，但不要假定使用者已作答。

## 練習階梯

### A. 回述與預測

讓使用者不看原片段，描述機制或預測結果。適合剛理解概念，成本低。

合成例子：

> 假設一個欄位只允許整數 1 到 10。輸入為 0 時，應在哪一步停止？
> 請說明停止後不應發生的下一個動作。

這不是要求執行 API 或測試。評量重點是條件、流程與副作用邊界。

### B. 仿作

給一個與原工作相似但數值、條件或資料結構不同的小問題，讓使用者寫草稿。

合成例子：

> 原例驗證單一值；新題要求驗證一組值，每個都須符合範圍。
> 請寫出檢查流程的偽碼，並提出一個有效與一個無效案例。

成功標準是覆盖所有值、保留錯誤處理、符合明確範圍。
不要求與 AI 原解答一模一樣，也不把語法格式當成機制理解。

### C. 除錯

提供小型錯誤片段或症狀，讓使用者定位一個關鍵問題。
標示「教學用錯誤」，不要讓它看起來是實際 repository 中已發現的 bug。

合成例子：

> 某個條件只在值小於下限且大於上限時拒絕輸入。
> 不執行程式，說明為什麼它無法攔截超出範圍的值，並提出修正構想。

安全題目不涉及真實 credentials、資料刪除或 remote mutation。

### D. 遷移與取捨

改變一個需求，請使用者判斷原方法是否還適用。

合成例子：

> 新需求允許欄位省略，但不允許有值時超出範圍。原流程哪一步要改？
> 哪一個已有案例應保留，哪一個新案例需要補上？

評量需求、機制、邊界與驗證，不只看能否寫出程式碼。

### E. 驗證設計

請使用者提出能證明或推翻某個行為的檢查，而不是直接執行它。

合成例子：

> 目前只有正常輸入的測試。若要支持「無效輸入不會被儲存」，你會增加什麼觀察？

對 Helm、Terraform 或部署教材，可以問證據分層，不安排 apply、install 或 sync 練習。

## 回答評估

使用適用的面向，不要求每題都有所有項目：

| 面向 | 看什麼 |
| --- | --- |
| 需求 | 是否抓到題目真正要求，沒有擴大範圍。 |
| 機制 | 是否正確追蹤輸入、條件、流程與結果。 |
| 邊界 | 是否處理題目中的失敗或特殊情況。 |
| 取捨 | 是否能說明採用與不採用方案的理由。 |
| 驗證 | 是否知道需要觀察什麼、已有 evidence 的限制。 |
| 安全 | 是否遵守授權、secret、repository 與 remote 邊界。 |

回饋用具體描述，不給沒有依據的百分比或「已精通」標籤。
合理替代答案也可成立；若需求未限定唯一解，不因與示範不同而判錯。
無法執行的草稿只能評估推理與靜態合理性，不能聲稱 runtime 正確。

## 能力狀態

對每個核心學習目標使用以下狀態，附一個可見依據：

- **能獨立說明/完成：** 使用者在本次條件下，不依賴答案完成相應任務。
- **需要提示：** 得到定位或結構提示後可以完成；指出仍需練習的步驟。
- **需要補課：** 即使提示後，關鍵機制仍混淆；回到較小的具體例子。
- **尚未評量：** 只聽講、跳過或沒有作答；不是答錯。

狀態只描述可見任務，不等於對整個技術領域的能力認證。
一次答對可能是記住答案；隔一段時間，用不同條件再測較能檢查保留與遷移。

## 延後複習流程

啟動延後複習時，先確認前次卡或摘要是否可見。沒有就請使用者提供非機密卡片
或指定工作，不自動搜尋歷史 sessions 或私人筆記。

1. **回憶：** 不先展示全部解說，先問一個核心機制問題。
2. **回饋：** 指出保留的理解與遺漏的概念，必要時補一小段。
3. **遷移：** 使用不同條件的小題，避免只複述卡片。
4. **更新摘要：** 在聊天中產出新的卡片版本，保留仍未評量的部分。

題目使用一題一答；不要在無答案問題旁附上會直接揭露解答的概念摘要。
使用者只想閱讀摘要時直接提供，但標記本次沒有評量。

可建議「下一次工作前」「隔日」「一週後」自行回來複習，不建立排程、不聲稱會提醒。
使用者沒有回答或中斷時，不捏造進步紀錄。

## 如何判斷這套流程有沒有幫助

觀察使用者是否能：

- 不看原答案解釋核心機制。
- 預測新的輸入或條件下的結果。
- 在較少提示下完成相似的小任務。
- 主動辨識證據缺口與可能失敗情境。
- 選出有判別力的檢查，而不是隨機嘗試。

這些是可用的觀察方式，不是已證實的收益。不要承諾 token、時間、程式品質或學習效率
必然改善。不以對話長度、題數或「看完全文」取代能力證據。
