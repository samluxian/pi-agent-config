# Fundamentals

- [Argo CD namespace creation and project permissions](argocd-namespace-creation-and-project-permissions.md): CreateNamespace requests destination namespace creation but does not replace AppProject resource permissions or Kubernetes RBAC.
- [Bound CI concurrency without widening retry scope](bounded-ci-concurrency-and-retry.md): CI capacity, job acquisition, mutual exclusion, parallel expansion, and retry are separate controls that must be sized and validated independently.
- [Bounded Markdown knowledge retrieval for coding agents](bounded-markdown-knowledge-retrieval.md): A compact keyword index can route an agent to a few atomic Markdown notes without loading the full knowledge base.
- [Separate CI execution from Kubernetes target selection](ci-runner-agent-and-cluster-context-boundaries.md): A GitLab runner executes a job, while an authorized GitLab Agent connection supplies Kubernetes contexts that select separate cluster identities and targets.
- [Deterministic context projection for tool results](deterministic-context-projection.md): A tool-result projection can reduce model context only when its bounded replacement preserves explicit completeness and fails open.
- [Replacing direct deployment with a GitOps handoff](direct-deploy-to-gitops-handoff.md): A delivery pipeline can hand off an immutable artifact reference through versioned desired state while a GitOps controller owns cluster reconciliation.
- [Evidence layers and causal restraint](evidence-layers-and-causal-restraint.md): Separate desired state, observed state, and runtime evidence before making a causal claim about agent behavior.
- [Evaluate Google Cloud IAM access by policy layer](gcp-iam-policy-evaluation.md): Google Cloud access depends on principal identity, inherited allow policies, applicable deny policies, principal access boundaries, and service-specific support rather than one role binding alone.
- [Gate GitOps delivery on explicit reconciliation evidence](gitops-reconciliation-health-and-pipeline-gates.md): Git revision, sync status, resource health, and application behavior are separate evidence layers that a deployment gate must select and time-bound explicitly.
- [Connect GKE scheduling constraints to autoscaling capacity](gke-scheduling-autoscaling-and-spot-capacity.md): Kubernetes schedules Pods from requests and placement constraints, while GKE cluster autoscaling can add only node capacity that satisfies those constraints and Spot capacity can disappear without availability guarantees.
- [Install CRDs before their custom resources](helm-crd-first-install-ordering.md): Helm guarantees first-install CRD ordering for the crds directory, not for CRDs rendered as ordinary templates beside their custom resources.
- [Preserve evidence across the Helm release lifecycle](helm-release-lifecycle-and-failure-evidence.md): Helm install, upgrade, rollback, and history operate on release revisions, while wait, atomic, cleanup, and history options determine what failure evidence remains.
- [Intent routing and adapter verification](intent-routing-and-adapter-verification.md): Typed intent routing narrows inspection commands, while adapters must validate and preserve the limits of their projections.
- [Combine Kubernetes tenancy boundaries instead of trusting namespaces alone](kubernetes-namespace-service-account-and-tenancy-boundaries.md): Kubernetes namespaces scope names and policy objects, but workload tenancy also depends on ServiceAccounts, RBAC, network policy, quotas, admission, and node or control-plane isolation.
- [Assign one purpose to each Kubernetes probe](kubernetes-probe-semantics-and-startup-order.md): Startup probes delay liveness and readiness checks, readiness controls endpoint eligibility, and liveness can restart a container without identifying its underlying failure.
- [Debug Kubernetes Service discovery from intent to endpoints](kubernetes-service-discovery-and-endpoint-debugging.md): Kubernetes Service diagnosis should trace DNS, Service ports and selectors, EndpointSlices, Pod readiness, and the listening process instead of stopping at one object.
- [Trace GKE load-balanced requests across control planes](kubernetes-to-gcp-load-balancer-request-path.md): A GKE Application Load Balancer request crosses Google Cloud forwarding, routing, backend, health-check, NEG, and Pod layers that must be verified separately.
- [Grant CI only the GitOps status access it uses](least-privilege-gitops-status-access.md): A CI status identity should receive project-qualified application read access while sync, update, delete, logs, defaults, and group grants remain separate decisions.
- [Design log exclusions around diagnostic evidence](log-exclusions-preserve-diagnostics.md): Cloud Logging exclusions control routing to each sink destination, so cost filters must preserve failure evidence and validate every storage and query path.
- [Give migration Jobs one rollout-ordering owner](migration-job-rollout-ordering.md): A one-time migration Job needs one lifecycle owner, explicit retry and cleanup behavior, and application-level validation before workload rollout proceeds.
- [Recognize the Node 24.15 and Yarn PnP EBADF regression](node-24-15-yarn-pnp-ebadf.md): Node 24.15.x changed ESM loader filesystem behavior in a way that triggered Yarn PnP EBADF failures; Yarn 4.14.1 worked around it and Node 24.16.0 restored compatibility.
- [Prompt guidance is not enforcement](prompt-guidance-is-not-enforcement.md): Prompt guidance can influence an agent but must be paired with deterministic controls for authority and execution boundaries.
- [Promote one immutable artifact with verifiable provenance](release-provenance-and-immutable-promotion.md): An immutable digest identifies exact artifact content, while provenance records how that artifact was produced; promotion should preserve both identities across environments.
- [Build and push images with rootless BuildKit in GitLab CI](rootless-buildkit-in-gitlab-ci.md): GitLab CI can run daemonless rootless BuildKit and push directly to a registry when runner security policy, credential helpers, and build context are configured explicitly.
- [Define recovery objectives before changing a datastore](rpo-rto-before-datastore-change.md): A datastore change needs explicit recovery point and recovery time objectives, a validated restore or fallback path, and application-level cutover checks before destructive or hard-to-reverse steps.
- [Authorize a Kubernetes CI runner to push to Artifact Registry](runner-identity-for-artifact-registry.md): A Kubernetes CI job can use its service account and Workload Identity Federation to obtain short-lived credentials while repository-level IAM authorizes Artifact Registry pushes.
- [Separate secret storage, delivery, authorization, and rotation](secrets-delivery-and-rotation-boundaries.md): A secret system must define where values are stored, who may retrieve them, how workloads receive them, and when applications observe rotated versions.
- [Treat a shared Helm chart as a versioned API](shared-helm-chart-contracts.md): A shared Helm chart exposes a values contract and a rendered-resource contract that require schema, compatibility, server, and runtime validation.
- [Keep one autoscaling control path per scale target](single-autoscaler-ownership.md): Independent replica writers can override each other, while one HPA or one KEDA ScaledObject can combine several scaling signals for a workload.
- [Select rollout strategy from the workload and volume contract](stateful-volume-safe-rollouts.md): Stateful rollout safety depends on revision overlap, identity, readiness, volume access and attachment semantics, and application-level fencing.
- [Keep authority with the subagent parent](subagent-parent-authority.md): A parent agent owns edits, approval, reconciliation, validation, and delivery while children return bounded read-only evidence.
- [Read Terraform plans as reconciliation proposals](terraform-plan-refresh-and-state-reconciliation.md): A Terraform plan compares configuration with refreshed prior state and proposes provider-defined actions, so its result is time-bound evidence rather than a permanent prediction.
- [Control Terraform replacement ordering explicitly](terraform-replacement-ordering-and-lifecycle.md): Terraform lifecycle rules can alter replacement ordering or reject selected actions, but they cannot remove provider constraints or external name and dependency limits.
- [Preserve resource identity during Terraform ownership migrations](terraform-resource-ownership-migration.md): Terraform migrations must preserve one state binding per remote object and prove the source and destination plans before ownership changes.
- [Prefer workload identity over service account key files](workload-identity-over-service-account-keys.md): Workload Identity Federation for GKE supplies short-lived workload credentials while IAM policies retain explicit authorization boundaries.
